## Trello-like Task Board — Implementation Plan

### Decisions (using best judgment since questions were skipped)
1. **Persistence → full-stack (MongoDB)**. The prompt says "prepare for future backend integration," but the entire CRM is backend-backed (FastAPI + Mongo) and the full dev stack is running. Building the real backend gives a refresh-safe, multi-user feature consistent with every other CRM module, and the frontend's `tasksAPI` service layer is the clean seam the spec wants.
2. **Drag-and-drop → `@dnd-kit`**. The spec is emphatic about smooth animations, no flicker, and the full move matrix (reorder cards within a board, move cards between boards, reorder boards). Native HTML5 DnD (used by the existing FlowBoard) can't deliver smooth transitions / sort-within-container cleanly. New React-19-compatible dependency.

### Backend — `backend/routers/taskboard.py` (new)
Mirrors `routers/units.py` exactly (the cleanest CRUD template): `router = APIRouter(prefix="/tasks", tags=["tasks"])`, module-level `db = None` + `set_db()`, local `async def _current(request)` wrapper around `get_current_user`, prefixed string IDs (`board_{hex[:12]}`, `card_{hex[:12]}`), `{"_id": 0}` projections, `HTTPException(404/403/400)` errors.

**Data model (single collection `task_cards`):**
- Board doc: `{ board_id, title, owner_id, position (int), created_at, updated_at }`
- Card doc: `{ card_id, board_id, owner_id, title, description, labels[], assignees[], due_date, position (int), created_at, updated_at }`

Splitting boards and cards into two collections (not nesting cards in board docs) avoids full-doc rewrites on every card move and scales to many cards.

**Endpoints** (all require auth; any authenticated user may manage — no unit gate, like the `/tasks` page itself):
- `GET  /api/tasks/boards` — list boards (sorted by `position`), each with its cards embedded (single round-trip for the board view)
- `POST /api/tasks/boards` `{ title }` → board
- `PATCH /api/tasks/boards/{id}` `{ title }` — inline rename
- `DELETE /api/tasks/boards/{id}` — also deletes its cards
- `POST /api/tasks/boards/{id}/cards` `{ title, ... }` → card
- `PATCH /api/tasks/cards/{id}` `{ title, description, due_date, labels, assignees }`
- `DELETE /api/tasks/cards/{id}`
- `POST /api/tasks/reorder` `{ board_order: [...], cards: [{ card_id, board_id, position }] }` — single bulk reorder call after every drag, persisting the new layout

**Mount** in `server.py` next to the other routers (`from routers.taskboard import router, set_db; set_db(db); api_router.include_router(router)`).

### UX / interactions (all from the spec)
- Default empty state with the exact copy given.
- Inline create for boards & tasks (autofocus, Enter/Esc/blur contract).
- Inline edit for board titles and card titles (no modal).
- Context menus (three dots) on boards and cards.
- Drag-and-drop via `@dnd-kit`: sortable cards within a board, cross-board card moves, and horizontal board reordering — with a drag overlay (no flicker) and spring animations.
- Horizontal scroll for boards; vertical scroll for cards inside each board; page never scrolls horizontally. Responsive: horizontal scroll on tablet, swipe on mobile.
- Keyboard accessible (focus rings), instant optimistic UI updates, `sonner` toasts, `data-testid` attributes throughout.

### Design system adherence
Hardcoded light hexes matching the CRM: app bg `#F7F6F3`, cards `bg-white` with `border-gray-100`/`#EAE7E0`, board columns `#F0EEE9`/`#FBFAF7`, gold accent `#C6A15B` for the empty-state + add buttons, `font-display` (Fraunces) for the page title. Dark mode works via the existing global `.dark` overrides (no Trello blue/green copied).
