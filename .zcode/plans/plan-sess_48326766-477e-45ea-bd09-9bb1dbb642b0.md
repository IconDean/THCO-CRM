## Project-Centric Task Board — Implementation Plan

### Branch
Work on `feature/tasks-board` (created from the current `page/proposals`). I'll branch first, then build.

### Decisions (best judgment, since clarifying questions were skipped)
1. **Project source → reuse Flow projects.** The app has one `projects` collection, exposed via `/flow/projects` (`flowAPI.listProjects`). Spec explicitly forbids duplicating project data. Project name = `name`, status = `stage_label`/`stage`, coordinator = `delivery_owner_name` (display) + the `is_delivery_coordinator` role flag (permission).
2. **Coordinator permission → existing `is_delivery_coordinator` flag + `super_admin`.** Reuses the app's current "Project Coordinator" concept (`flow.py` gates Stage 1→2 on exactly this flag). Spec says "do not alter the existing permission architecture."
3. **Backward compat:** old boards/cards have no `project_id`. I'll scope new boards to a project and treat legacy (no `project_id`) boards as orphans that are simply not shown in any project workspace (they remain in the DB untouched).

### Backend — `backend/routers/taskboard.py` (extend existing)

**Data model changes (additive):**
- `task_boards` doc: add `project_id` field.
- `task_cards` doc: unchanged structurally (already has `board_id`; `project_id` is implied via its board, but I'll denormalize it onto cards for fast filtering).

**Endpoint changes:**
- `GET /api/tasks/boards?project_id=<id>` — filter boards by project (existing `list_boards` becomes project-scoped; omitting `project_id` returns `[]` for safety, since the UI always passes it now).
- `POST /api/tasks/boards` — `BoardCreate` gains required `project_id`; `create_board` stores it + a `created_by_name`, returns board with empty cards.
- **Board templates**: `DEFAULT_BOARD_TITLES = ["UI/UX Tasks","Dependencies","Backlog","Frontend Todo","Backend Todo","QA Review","Ready For Merge","Done"]` (duplicate QA Review removed) — defined as a constant; the dropdown is built from it on the frontend.
- `GET /api/tasks/projects/summary` — **new** endpoint: lists Flow projects (reusing `db.projects`) annotated with `board_count` and `task_count` per project (aggregated from `task_boards`/`task_cards`). This powers the Projects workspace grid without duplicating project data.
- Coordinator gate helper: `_is_coordinator(user)` = `user.role == "super_admin" or user.is_delivery_coordinator`. Applied to create/rename/delete board, create/edit/delete card, reorder — returning 403 otherwise. (Read endpoints stay open to any authed user.)
- `team-members` for assignees: keep existing `/tasks/team-members`, but also add the project's `delivery_owner` + `assigned_engineer` to the candidate pool so project members appear.

### Frontend — restructure `/tasks` into two views

**New flow:** `Tasks.jsx` (Projects workspace) → select project → `TaskBoard` (project-scoped). I'll keep `/tasks` as the route and manage the selected-project state in `Tasks.jsx` (no new routes needed; "Back to Projects" just clears selection). This keeps the navbar pointing at one place.

**Files to add/modify:**

1. **`Tasks.jsx`** (rewrite) — owns `selectedProjectId` state:
   - **No selection → Projects Workspace**: a responsive grid of project cards (`flowAPI.listProjects` + per-project board/task counts via `tasksAPI.listProjectSummary`). Each card shows **Name, Status (stage_label), Coordinator (delivery_owner_name), # Boards, # Tasks, progress**. Clicking sets the selection.
   - **Selection → `<TaskBoard projectId={selectedProject} project={projectObj} onBack={…} />`** with the project name prominent at top + a "← Back to Projects" action.
   - Permission flag `canManage` = current user's `is_delivery_coordinator`/`super_admin` (from `UserContext`), threaded into TaskBoard to gate Add-board/Add-task/menus.

2. **`TaskBoard.jsx`** (extend) — accept `projectId` + `project` + `canManage` props:
   - `load()` calls `tasksAPI.listBoards(projectId)` instead of global.
   - All mutations pass `projectId` through.
   - Pass `canManage` to `BoardColumn`/`AddBoard`/`AddTask` to disable create/edit/delete for non-coordinators (read + drag-disabled).

3. **`AddBoard.jsx`** (rewrite trigger) — replace the immediate text input with a **dropdown** of `DEFAULT_BOARD_TITLES`:
   - Clicking "Add another board" opens a Popover listing the 8 predefined titles (excluding any already used in this project).
   - Selecting a title instantly creates the board (`onCreate(title)`).
   - Bottom: **"+ Add Custom Board"** → reveals the existing inline input (autofocus, Enter saves, Esc cancels, trim, dedupe-within-project, custom names added to the dropdown list for that session).
   - Hidden entirely when `!canManage`.

4. **`api.js`** — extend `tasksAPI`: `listBoards(projectId)`, `createBoard(projectId, title)`, `listProjectSummary()`. Keep `reorder`, card CRUD, labels, team-members.

5. **`BoardColumn.jsx` / `TaskCard.jsx`** — accept `canManage`; hide menus + disable drag handles when false. Board column shows the editable title only for coordinators.

6. **`ProjectsWorkspace.jsx`** (new component) — the grid/list UI extracted for clarity, used by `Tasks.jsx`.
